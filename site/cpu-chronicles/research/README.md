## 使用规则

1. **先查时间与事件类型。** 架构公开、芯片宣布、预售、CPU 上市和 OEM 整机上市可能是不同日期。只查到年或季度的记录保留原精度。
2. **再查产品归属与配置。** 品牌不是微架构，整机厂商不一定是 CPU 设计厂商；同名芯片的不同核数、功耗、缓存和封装不能合并为同一个测试对象。
3. **引用评价时回到原测试。** 本材料区分厂商自述、原作者独立实测和后来的技术解释；性能百分比只对原文的负载与测试条件成立。
4. **检查证据状态。** 官方入口、原始手册镜像、可读评测、仅搜索索引可见的旧文、待查日期分别处理。目录链接用于继续定位，不自动证明其下所有型号的发布日期。

## 覆盖与缺口

本材料建立三家的历史产品谱系，**不等于逐 SKU 数据库，也不宣称所有记录的证据都同等完备**。单个家族的一行可能合并多个发布批次；每家文件末尾列明仍待补齐的旁支、日期和原始测试。取消项目、路线图和已宣布但未上市产品不能计为已经上市。

较早的产品优先依靠厂商手册、当年年报和历史年表：手册印刷年能证明彼时已有该产品资料，不能自动证明那一年就是首次发布。较新的产品优先依靠有日期的官方发布稿，并继续核查可用性文字。

价格是本轮的明确缺口：未建立全家族的首发价格表，也未统一地区、币种、OEM/零售和整机/裸 CPU 口径。各文件仅在原文证据充分时记录，不使用今天的二手价补历史发布价。

部分 AnandTech 历史评测原地址在本次读取时已重定向，虽然搜索引擎仍保留旧文摘要。相关链接只作归档线索；需取得原作者正文或档案快照后，才能补录未核实的具体图表与数字。正式引用时建议同时保存原始 URL、归档 URL、作者、原文日期和资料读取日。
